文中的 GM 指设备全局内存，UB 指核内统一缓冲区；AIV 执行向量计算，MTE2、MTE3 分别承担输入搬入与结果写出。

## 元素分解与分核规则

LogSigmoid 对每个元素独立计算 \(y=\log\sigma(x)\)，没有沿某个轴累加的依赖。因此，调度先把张量展平成长度为 \(N\) 的连续数组，再把互不重叠的连续区间交给各个 AIV。输入形状只参与元素总数计算，数据类型和 \(N\) 决定后续路径。一次非空调用只发射一个 kernel；核之间没有中间结果交换，也不需要跨核同步。所有数学运算都在设备向量单元完成，FP16 路径直接使用 half 运算，FP32 路径直接使用 float 运算。

主要计算路径采用

\[
\log\sigma(x)=\min(x,0)-\log\bigl(1+\exp(-|x|)\bigr).
\]

它把指数函数的输入限制在非正区间。向量计算分成两支：一支生成 \(-|x|\)，依次经过 Exp、加一和 Ln；另一支保留 \(\min(x,0)\)，最后做减法。Ln 和 Mins 之间没有数据依赖，可以在同一段向量计算中分别发出，再在最终 Sub 前汇合。实现始终保留原输入，直到 Mins 已消费该输入；临时数组承载指数、对数这条链，最终结果覆盖输入所在的本地槽。

分核先确定可用核数 \(C\)：调用方未给出有效值时取 1；当 \(4096\le N\le262144\) 时，最多使用 32 核；其他规模使用传入的可用核数。接着按类型选定每核初始工作粒度 \(g\)：FP32 通常为 1024 个元素，\(N\le256\) 时为 64；FP16 通常为 512，\(N\le2048\) 时为 128。初始核数、对齐后的区间长度及最终核数分别为

\[
P_0=\min\bigl(C,\lceil N/g\rceil\bigr),\qquad
B=64\left\lceil\frac{N}{64P_0}\right\rceil,\qquad
P=\lceil N/B\rceil.
\]

第 \(i\) 核负责从 \(iB\) 开始、长度为 \(n_i=\min(B,N-iB)\) 的区间。这里的 64 是元素数，分别对应 FP32 的 256 字节和 FP16 的 128 字节。重新计算 \(P\) 可以去掉对齐后不再需要的空核。这个规则同时限制小张量的分核开销，并使绝大多数核处理相同长度、对齐一致的连续数据。

## 单 tile 的专用计算

设备路径按下面的优先级选择。表中的 \(B\) 是每核区间长度，单 tile 的容量不等于最后一核的有效元素数。

| 进入条件 | 每核计算组织 |
|---|---|
| FP32 的 \(B\in\{64,512,1024\}\) | 固定容量、固定 repeat 的单 tile 路径 |
| FP16 的 \(B\in\{128,512,2048\}\) | 固定容量、固定 repeat 的单 tile 路径 |
| 其余路径中，\(g<512\) 且 \(B\le128\) | 容量 128 的通用单 tile 路径 |
| 其余 \(B\le512\) | 容量 512 的通用单 tile 路径 |
| 其余 \(B\le4096\) | 容量 4096 的通用单 tile 路径 |
| \(B>4096\) | 每核内部循环，按 tile 双缓冲流水处理 |

单 tile 路径只需要一个输入兼输出区和一个临时区。MTE2 按真实长度搬入输入，向量单元等待搬入完成后计算，随后通过 V→MTE3 事件发布结果，再由 MTE3 写出。核返回前等待输出退休。通用路径使用 counter mask，把运算有效长度设置成 \(n_i\)，因此无需为尾核另发 kernel。固定路径则使用普通满 mask 和编译期 repeat：FP32 的三个固定长度分别对应 1、8、16 个 repeat，FP16 的三个固定长度分别对应 1、4、16 个 repeat。即使最后一核不足固定容量，也只写回真实元素；各 lane 互不混合，补齐区域的计算不会进入有效输出。

固定 FP32 路径还有一项明确的数学分派。它先令 \(z=\min(x,10)\)，再依次计算 Exp、加一、Ln，输出 \(z-\log(1+\exp z)\)。这条链共五个向量算子，输入上限也限制了 Exp 的范围。对有限的 \(x\)，当 \(x\le10\) 时，该表达式与 LogSigmoid 数学等价；当 \(x>10\) 时，截断引入的绝对误差不超过 \(\log(1+e^{-10})\approx4.54\times10^{-5}\)，这里尚未计入各算子的浮点舍入。固定 FP16 路径采用前述稳定公式，并通过设置符号位直接生成 \(-|x|\)，省去单独的 Abs、Muls 组合。两种路径均保持输入类型，不增加整段类型转换和中间张量搬运。

## 双缓冲与槽位寿命

大区间的 tile 大小由类型和总元素数决定。FP32 固定为 8192；FP16 在 \(N\le2^{21}\) 时取 8192，在 \(2^{21}<N\le2^{24}\) 时取 16384，更大时取 32512。上述选择只在 \(B>4096\) 的流水分支内生效。每个 kernel 在 UB 中放置两个大小为 TILE 的数据槽，以及一个同样大小的计算临时区，另留对齐间隔和所需常量空间。两个数据槽轮流承担输入和输出，不再另设两个输出缓冲。最大 half tile 的三个主体区域共占 195072 字节；普通双缓冲路径连同间隔和常量区的地址上界为 195840 字节，落在 192 KiB 内。

流水通过显式事件管理这些区域的寿命，没有 TQue 队列。开始时先把第一个 tile 搬入槽 0。第 \(t\) 轮使用槽 \(t\bmod2\)，并尽早向另一个槽预取第 \(t+1\) 个 tile。首次使用槽 1 可以直接搬入；以后复用槽之前，必须等该槽上一次的 MTE3 写出完成。预取发出后，当前轮等待本槽的 MTE2→V 事件，执行向量计算，再等待 V→MTE3 的交接事件并写出结果。写出完成信号使用 MTE3→MTE2 事件，作为两轮之后重新覆盖本槽的凭据。

这样，MTE2 可以搬入下一 tile，V 可以计算当前 tile，MTE3 可以写出前一 tile。它们实际能重叠多少由数据依赖和搬运吞吐决定：若输出尚未退休，下一次输入必须先等待，不能抢占同一块 UB。共享临时区则始终只供当前 tile 的向量链使用。循环结束后分别收回两个槽的输出完成事件，最后执行收尾屏障，保证 kernel 返回时没有仍在读取这些槽的输出 DMA。

流水内部也区分完整 tile 和尾 tile。普通 FP32 路径在完整 8192 元素 tile 上广播符号位常量，直接生成 \(-|x|\)，随后执行 Exp、Adds、Ln、Mins、Sub；尾 tile 改用 counter mask 和 Abs、Muls 生成负绝对值。普通 FP16 的 8192、16384 tile 使用符号位版本，32512 tile 使用 Abs、Muls 版本。所有这些路径都只在核内顺序推进 tile，不把同一元素的运算拆到不同核心。

## 按容量选择 L2 访问策略

缓存调度以运行时查询到的 L2 容量 \(C_{L2}\) 为依据。设整个张量的字节数为 \(S\)，只有标准核区间 \(B\) 大于 TILE、\(C_{L2}/2<S\le C_{L2}\)，且“完整输出的保守 footprint，加上每核第一个输入 tile 的保守 footprint”不超过 \(C_{L2}\) 时，才启用输入缓存分派。footprint 按可能的起始对齐及缓存行边界向上留量，尾核按实际首 tile 长度计算。设备能力查询失败或容量条件不成立时，使用普通路径。容量按当前设备查询并缓存，不把某个固定 L2 大小写进调度假设。

进入这条路径后，第一 tile 的输入仍按默认策略搬入；随后才给输入 GM 张量设置 CACHE_MODE_DISABLE，后续预取使用该提示，输出始终保留默认缓存策略。其空间安排是让输出与各核首 tile 有机会留在 L2，同时减少后续输入流对它们的占用。FP32 缓存路径仍对完整 tile 使用符号位计算、对尾 tile 使用 counter mask；FP16 缓存路径统一使用 Abs、Muls、Exp、Adds、Ln、Mins、Sub 七步，缓冲交换与事件顺序保持一致。缓存提示只改变访存策略，不改变数据划分、元素计算次序或输出范围。

## 尾块与退出状态

尾部处理贯穿三个层次：分核时只让最后一核缩短有效区间，分 tile 时用剩余元素数确定最后一块，搬出时再按真实字节数截断。输入由 DataCopyPad 搬入，向量运算使用本地容量或有效 mask，输出不会写入补齐区。修改 counter mask 的路径在退出前恢复普通 mask；需要设置 half 控制位的流水路径保存原值并在结束时恢复。每核的区间、每个缓冲槽的覆盖时刻和最终写出范围都由这些规则固定下来。
